# 家庭辅食成功食谱 MVP

## 1. 产品定义

帮助家庭把实际做成功的宝宝辅食，快速沉淀为可共同维护、查找和复用的家庭食谱。

产品不记录每一餐，也不收集尚未实践的网络食谱。家庭成员主动判断某个做法值得留下，才进行收录。

## 2. MVP 要验证的价值

1. 制作者即使没有照片，也能在较短时间内留下有复用价值的经验。
2. 其他家庭成员能找到这份食谱，并看懂下次应当怎么做。
3. 家庭可以持续修正同一份食谱，而不是产生多个互相冲突的版本。

建议用以下任务作为可用性验收，而不是用记录总量证明价值：

- 新用户能在 30 秒左右完成一次快速收录。
- 家庭成员能在 15 秒左右找到指定食谱并定位关键经验。
- 没有照片、没有精确用量时仍能完成正式收录。
- 修改后，其他家庭成员能看到最新版本，并能识别最后修改人。
- 发生误改时，可以从修订记录恢复旧内容。

## 3. 用户与归属

### 家庭成员

每位成员使用自己的个人身份加入家庭。所有家庭成员均可查看、收录、编辑和复用食谱。

### 家庭管理员

家庭中保留一名管理员，仅负责邀请和移除成员。管理员不拥有额外的食谱内容权限。

### 内容归属

食谱属于家庭，不属于创建者个人。创建人和最后修改人只作为贡献信息显示。

## 4. MVP 范围

### 包含

- 创建家庭或通过邀请加入家庭
- 浏览家庭食谱
- 按名称、食材、类型、核心原料标签和关键经验搜索
- 按辅食类型进行轻量筛选
- 快速收录成功做法
- 逐步完善食材、步骤、适用阶段、辅食类型、核心原料标签和照片
- 编辑当前家庭食谱
- 复制一份食谱作为新的独立食谱
- 自动保存简单修订记录
- 查看最后修改人，并从旧版本恢复
- 简单的成员邀请和移除

### 暂不包含

- 每餐喂养记录和打卡
- 网络食谱收藏和“想尝试”列表
- 公共社区、关注和点赞
- 今日菜单、库存或营养推荐
- 自动判断食物安全、过敏风险、适用月龄或营养均衡
- 复杂权限、内容审批、版本分支和自动合并
- 基于进食量自动判断是否成功

## 5. 家庭食谱的数据结构

### 正式收录的最低内容

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | 家人能够识别的菜名 |
| 关键经验 | 必填 | 至少一条能帮助下次制作的实质信息 |

### 可逐步补充的内容

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 食材 | 选填 | 可逐项添加，用量可以留空 |
| 步骤 | 选填 | 有顺序的制作过程 |
| 适用阶段 | 选填 | 描述成品形态或进食能力，不给出月龄保证 |
| 辅食类型 | 选填 | 单一轻量分类，用于快速筛选，不自动判断 |
| 核心原料标签 | 选填 | 建议不超过三个，用于识别和搜索，不替代食材清单 |
| 照片 | 选填 | 有图时帮助辨认，无图不显示占位框 |

### 系统自动记录

- 所属家庭
- 创建人和创建时间
- 最后修改人和最后修改时间
- 修订记录
- 当前状态

## 6. 内容状态

### 待补条目

只有名称、尚未填写关键经验。可以保留供用户稍后继续，但不作为可复用食谱参与默认展示和搜索结果排序。

### 家庭食谱

至少包含名称和关键经验，代表家庭实际做成功过的当前做法。

涉及食材、比例或关键步骤的实质改变，应当在实际制作成功后再保存到当前食谱。首版通过界面文案提醒，不增加审核流程。

## 7. 核心流程

### 7.1 快速收录

1. 用户在食谱库点击“记录成功做法”。
2. 输入名称。
3. 输入关键经验，输入框提供一条具体示例帮助理解。
4. 点击“保存”。
5. 进入食谱详情；缺少详细内容时显示“补充食材和步骤”，但不阻塞完成。

如果只填写名称，用户可以明确选择“保存为待补充”。内容进入待补条目，不伪装成完整食谱。

待补条目可以从首页进入独立清单。用户选择一条后继续填写成功关键；保存为正式食谱时，原待补条目从清单中移除。

### 7.2 查找和复用

1. 用户打开家庭食谱库。
2. 浏览最近更新和轻量清单，按辅食类型筛选，或搜索名称、食材、标签和关键经验。
3. 打开食谱详情。
4. 首先看到关键经验，然后查看食材和步骤。

首版不要求用户点击“开始制作”或记录本次进食结果，避免重新变成逐餐记录工具。

### 7.3 完善或修正

1. 家庭成员从详情页进入编辑。
2. 修改已有内容或补充可选字段。
3. 按需补充辅食类型和不超过三个核心原料标签。
4. 界面提醒“确认做成功后，再更新当前食谱”。
5. 保存后生成修订记录，并显示最后修改人。

### 7.4 恢复旧版本

1. 用户从详情页打开修订记录。
2. 按修改人和时间查看旧内容。
3. 选择“恢复为当前做法”。
4. 恢复本身形成一条新的修订记录，不删除历史。

## 8. 产品原则

- **不为了记录而记录**：没有值得复用的成功经验，就不要求产生内容。
- **先留下，再完善**：结构服务于复用，不能成为收录门槛。
- **文字先于照片**：页面必须在完全没有图片时仍然成立。
- **关键经验优先**：打开食谱时，先回答“下次怎样做容易成功”。
- **家庭共同维护**：不以创建者为中心，不设计内容审批流程。
- **只表达家庭经验**：不把家庭反馈包装成专业、安全或营养结论。

## 9. MVP 完成标准

- 一个新家庭可以创建空间并邀请另一名成员加入。
- 任一成员可以无照片快速收录一份正式食谱。
- 另一名成员可以搜索并查看食谱的关键经验。
- 家庭成员可以按辅食类型筛选，并通过核心原料标签快速识别食谱。
- 任一成员可以补充食材和步骤，其他成员能同步看到修改。
- 用户可以查看简单修订记录并恢复旧内容。
- 待补条目与正式食谱在界面上有明确区别。
- 暂不包含范围中的能力没有混入主要导航和收录流程。
