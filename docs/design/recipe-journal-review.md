# 食记（recipe-journal）页面设计 Review（2026-08-30）

范围：`codex/recipe-journal` 分支新增的食记功能——食记 tab 页、单次记录表单（recipe-attempt-edit）、详情页「最近记录」嵌入区、底部导航 2→5 栏改造、设置页 tab 化。
基准：现行设计规范（app.scss token、主流程页面语法、`docs/design/recipe-journal.md` 功能设计文档）。

## 总评

**这个功能的"页面内设计"质量相当好，真正的偏差集中在"页面外"——主导航结构、跨页组件和少量色彩/格式决策上。** 表单页（recipe-attempt-edit）几乎是教科书级的规范执行：纸面 + 细线分节、白卡描边 picker、洗底选中态、分段控制、吸底保存、红字删除、来源页 navbar——全部对齐。食记列表页的白卡、衬线标题、高度+颜色双编码竖条也都成立。以下问题按影响排序。

## 做得好的（保持）

- **表单页语法全对齐**：分节细线、`field-label`、白卡 picker（与新 P0-3 输入语言一致）、三档接受度的卡片单选 + `brand-wash` 选中态、「按原食谱/有调整」分段控制、吸底保存、红字删除链接、navbar 显示来源页「食记」
- **竖条图的信息设计**：高度 + 颜色双编码（不依赖色觉）、不补空日期、不做打卡化——功能设计文档（recipe-journal.md）里"不是量化仪表盘"的克制值得表扬
- **详情页嵌入位置合理**（步骤之后、footnote 之前），空态文案给出了行动指引
- loading/toast/navbar/aria-label 等工程规范全部遵守

## 偏差清单

### P1-1 主导航从 2 tab 扩到 4 tab + FAB，信息架构变更未经设计评审
设计稿的导航宪法是「食谱库 / FAB / 家庭」。现在变成 5 列：食谱库 / 食记 / FAB / 家庭 / 设置。连带三个视觉问题：
- tab 标签字号硬编码 `20rpx`（低于 `--fs-caption` 22rpx，未走 token）；图标从 42 降到 38 补救拥挤
- 390px 宽度均分 5 列每列约 150rpx，「食谱库」三字已接近换行临界
- **「食记」用 clock 图标，但 clock 在全 App 已是"修订记录/当前版本"的语义**（详情 meta、历史时间线），一符两义

这不是"实现错了"，而是结构决策缺一次评审：食记作为一级 tab、设置从家庭页独立出来，都是合理的 IA 候选，但应该和"食记只作为详情内嵌区 + 库筛选"方案对比后拍板。若维持 5 栏：字号回 token、食记换专属图标（建议新增"笔记本"图形）。

### P1-2 食记页「记一次」橙色横幅：一屏三处橙 + 同一动作双量级
横幅是全 App 第一个通栏 brand 底按钮（116rpx 高 + 半透明白圆 + 双行文案）。加上 FAB 和 tab 激活态，食记页一屏三处橙，打破了"橙色只留给唯一主操作、且以轻量形态出现"的预算。而且同一动作在详情页是右上角橙色**文字链接**（recent-action）——两处量级相差悬殊，用户会困惑哪个是"正式入口"。
建议：横幅降级为白卡 + 左侧橙色图标 + 橙色标题（类似"添加主图"空态块的量级），或虚线描边轻按钮（设计稿邀请卡的语法）。FAB 保持全局唯一的实体橙。

### P1-3 新语义色未走 token，且两处重复定义
`#cba77b`（能接受）、`#9b8a7d`（不太接受）在 journal.scss 和 detail.scss **各写了一遍**（recent-bar 与 attempt-bar 两套几乎相同的样式，13 行 + 31 行重复代码）。问题：
- 新语义色没有进 token 表——对照 amber/emerald 的先例，应定义为 `--sand: #cba77b`、`--bark: #9b8a7d`（命名待定）
- 两处色值/高度比例不同步的风险（journal 92/62/34 vs detail 72/48/26，比例一致但纯靠手维护）
建议：token 化 + 提取共享的 chart 样式（放 app.scss 或做一个 mini 组件）。另外两个中性色的纸面区分度偏弱，深度比对后确认。

### P1-4 日期格式破例：表单里显示 ISO「2026-08-30」
全 App 日期语言是「8月30日」「3 天前」（食记列表页自己也用了 `dateLabel` 中文格式）。记录表单的日期选择器字段却直接显示原始 `occurredOn`。应复用同一格式化函数。

### P2-1 食记页头部的常驻副标题
「记下实际做过的感受，慢慢把食谱变得更适合宝宝」是一句产品文案常驻页头——说明文字泛滥的旧问题回来了。库/家庭页头部都只有功能性 meta。建议删掉或移入空态（空态文案已经承担了引导职责）。

### P2-2 空态出现第三种语法
食记空态 = 虚线盒子 + 衬线标题 + 文案；食谱库空态 = 纯文字；详情嵌入区空态 = 纯文字行。三种并存。dashed 盒子形态本身不错，建议定成空态标准并回铺到其他页（或者统一去掉盒子）。

### P2-3 横幅内帮助文字对比度
白色 78% 透明度文字叠在 #bf5924 上，caption 字号下对比度约 3:1，低于 4.5:1 标准。若按 P1-2 改成白卡，此问题自动消失。

### P2-4 「记一次」动作命名与 FAB 的分工说明
现在 FAB = 添加食谱、横幅 = 记一次，逻辑成立（功能文档也写明了），但入口图形语言未传达这个分工：横幅的白色圆形 + plus 图标与 FAB 高度相似，容易让人以为 FAB 也能"记一次"。降级横幅后此问题缓解；也可考虑横幅图标换成 pencil/check 类"记录"语义。

## 需要产品拍板

1. **导航结构**：维持 5 栏（则修字号/图标语义），或回归双栏 + 食记降级为详情内嵌区 + 库筛选入口
2. **横幅量级**：降级为轻量白卡（推荐），或保留横幅并把详情页"记一次"提升为同量级
3. **设置 tab 化**：方向认可（不再寄生家庭页），但同步要删掉家庭页残留的设置相关代码引用（openSettings 已删，确认无死代码）

## 一句话总结

食记功能的**页面内设计是近期新功能里执行最好的一块**，表单页几乎可以直接当规范范例；需要修的是它带来的**系统级改动**——导航扩容、橙色预算、新语义色 token 化——这些恰恰是"页面内很好、页面间打架"的老问题的重演，建议在合并前把 P1 四项处理掉。
