# 家庭食谱选项管理

## 1. 设计结论

“辅食类型”和“适用阶段”是家庭共同维护的单选食谱选项，不是核心原料标签。所有有效家庭成员都可以添加和删除，修改后对全家生效。

删除某个选项表示家庭不再使用这一分类：正在使用它的当前食谱会变为对应字段“未选择”，其他内容不变。旧修订快照可以保留当时文字，但恢复时必须按当前家庭选项过滤，不能让已删除选项重新出现。

## 2. 删除语义

以删除辅食类型“粥类”为例：

1. 删除前显示当前有多少份可见食谱正在使用。
2. 云函数先把“粥类”从家庭可选项移除，新建、编辑和历史恢复立即不能再写入它。
3. 云函数清除家庭内所有食谱当前内容中的“粥类”，并递增食谱并发版本。
4. 不改变食谱修改人、更新时间，也不为家庭配置维护批量生成修订记录。
5. 已打开旧编辑页保存时会因版本变化发生冲突，不能把删除值覆盖回来。
6. 以后重新添加同名选项，先清理可能残留的旧引用，旧食谱仍保持未选择。

食谱列表读取还会按当前家庭配置过滤 `type` 和 `stage`。这层读取约束保证批量清理即使因网络中断尚未完成，用户也不会看到已删除选项。

## 3. 设置页交互

设置页提供一个“食谱选项”入口，副文案为“管理辅食类型和适用阶段”。独立管理页分为两个区块：

- 每个选项显示名称和使用中的食谱数量。
- 每个区块末尾提供添加入口，新选项追加在末尾。
- 删除使用页面内底部确认面板，不依赖原生确认弹窗。
- 删除确认明确说明有多少食谱会变为未选择，以及其他内容不会改变。
- 页面说明“所有家庭成员都可以修改，变更会对全家生效”。

首版不提供重命名和拖动排序。重命名的历史语义不清楚，用户可以通过删除旧项、添加新项完成明确迁移。

## 4. 数据与权限

家庭文档保存：

```ts
interface RecipeOptions {
  foodTypes: string[]
  stages: string[]
  version: number
}
```

老家庭没有配置时使用原固定选项作为首次默认值；空数组必须保留为空，表示家庭主动删除了全部选项。每类最多 20 项，名称去除首尾空格后最多 20 字，同类名称不能重复。

所有接口都从微信身份解析有效家庭成员，不接受客户端提交家庭或角色。添加、删除使用 `expectedVersion`，防止两位成员同时修改时互相覆盖。

食谱仍保存选项文字。写入、复制和历史恢复都在云函数事务中读取最新家庭配置，只保留当前有效值。

## 5. 首版验收

- 老家庭打开管理页可看到原有默认选项和准确使用数量。
- 任意有效家庭成员都能添加、删除；非成员不能访问。
- 新选项立即出现在编辑页，保存后可在详情和首页筛选中使用。
- 删除未使用选项不会改变任何食谱。
- 删除使用中的选项后，相关食谱变为未选择，名称、成功关键、图片、食材和步骤不变。
- 删除导致的版本变化能阻止旧编辑页覆盖。
- 恢复包含已删除选项的旧修订时，该字段仍为未选择。
- 重新添加同名选项不会让旧食谱自动重新关联。
