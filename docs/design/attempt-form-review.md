# 记录表单（recipe-attempt-edit）深度 Review（2026-08-30）

方法：截图与编辑页（f2）并排对照，从"这个页面本质是什么"出发推导，而非逐像素挑错。

---

## 一、第一性判断：这是一个被装进"表单骨架"里的便签

**这个页面的本质**：用户刚喂完宝宝，30 秒内记下"哪道菜、哪天、接受度、按没按原方"。它是全 App 频率最高的写操作。它的心理模型是**在便签上打个勾**，不是填一张表。

**但实现用了编辑页的重表单骨架**：四节分栏（食谱/日期/接受程度/这次怎么做的）、细线分隔、label+控件逐节堆叠。对照编辑页就能看出重量错配的根源：

> **编辑页的每个分节里都有"内容"**——衬线的成功关键、图片、食材行、胶囊。label 是内容的目录，骨架被内容填满了。
> **记录表单的每个分节里只有一个孤零零的控件**——一根白卡 picker、三张选项卡。骨架独自站立，所以整页显得空、散、灰。

这就是"难看"的第一性根源：**不是哪个组件画错了，是页面的重量模型选错了**。

## 二、逐元素对照（现状 vs 编辑页参照 vs 应然）

| 元素 | 现状 | 编辑页参照 | 问题与应然 |
| --- | --- | --- | --- |
| 食谱名「如玉烩饭」 | 衬线 38rpx 悬在页头，下跟一行灰字说明 | 名称是 **46rpx display 衬线**，页面绝对主角 | 名字在这里是便签的标题，应该升到 display；说明行是常驻产品文案（navbar「记下这一次」已表意），删 |
| 分节 label「食谱/日期/…」 | 裸灰字悬在大留白里，节间距大而不均 | label 带图标、紧贴控件（margin 14rpx）、节奏密集 | 轻记录不需要四个节——见重构方案 |
| 食谱/日期选择 | 白卡描边字段 ✓（语言对）+ **微信原生滚轮弹窗** | 无对应 | 弹窗是全 App 唯一的"系统视觉时刻"，与暖纸面断裂；需自实现 sheet 选择器 |
| 接受程度三选项 | 白卡三张 + 左侧漂浮色条 + wash 选中 | 分类是**胶囊 chips**（单选、橙底白字选中） | 三个问题：色条语义不明（是图表语言不是表单语言）、三卡边框堆叠（gap 12 < 内边距 18，粘连）、选中态弱（文字不橙） |
| 「按原食谱/有调整」 | 分段控制（白底选中+阴影）✓ | — | **这个组件是全页最好的**，语法正确，保留 |
| 调整说明 textarea | paper-deep 灰底（未随 P0-3 换白卡） | 已换白卡描边 | 跟上白卡语言 |
| 保存栏 | 吸底主按钮 ✓ | 同 | 保留 |
| 删除 | 红字居中 ✓ | — | 保留 |

补充观察：整页文字全是 ink-2 中灰（label/说明/占位），没有一级重文字压阵，密度又低——"灰蒙蒙"的感受来源。标题升级 + 说明删除后自然解决大半。

## 三、系统 picker 的自实现方案

用户明确要求替换系统滚轮。两个弹窗都可以收进 **quick-capture sheet 的容器语言**（白底、把手、圆角、上滑入场）：

1. **食谱选择 sheet**：衬线食谱名列表 + 每行"记录过 N 次"meta + 选中橙勾。数据现成（食记页已在聚合）。
2. **日期选择 sheet**：`picker-view` 原生滚轮芯 + 自绘外壳（暖纸底、品牌色确认按钮）——滚轮交互保留原生手感，壳是 App 的。不建议自绘整月日历（工程量三倍，收益低）。

## 四、重构方案（两档）

### 方案 A：便签式重构（推荐）

页面从"四节表单"变成"一张便签 + 一个问题"：

```
navbar：食记 ← ｜ 记下这一次
────────────────────────────
妈妈炒饭                      ← display 衬线，便签标题（新建时点开选食谱 sheet）
8月30日 · 按原食谱             ← 行内元数据，点任一处弹对应 sheet 修改
────────────────────────────
宝宝这次的接受程度？            ← 唯一的问题（label 语法同编辑页）
(很喜欢) (能接受) (不太接受)    ← 三颗 option-chip，选中=橙底白字
▸ 这次有调整                  ← 默认收起，展开显示白卡 textarea
────────────────────────────
[        记下这一次        ]   ← 吸底（保留）
```

- 控件组数 4 → 1.5，页面高度约省 40%，"30 秒记录"的心理模型成立
- chip 语法直接复用编辑页分类的 `option-chip`（含选中态），零新组件
- 食谱/日期从"表单字段"降为"便签元数据行"，sheet 选择器负责修改
- 编辑已有记录时同一布局，底部追加删除链接

### 方案 B：保守修缮（不动结构）

保持四节骨架，只修：
1. 标题升 display、删 intro 说明行
2. label-控件间距规范（label margin 14rpx、节内 padding 收敛到统一档）
3. acceptance 三卡改三颗胶囊 chips（同编辑页分类语法，色条退场——颜色语义留给图表）
4. 「有调整」textarea 换白卡描边
5. 两个 sheet 选择器（同方案 A）

## 五、建议

选 A。理由：这个页面会是全 App 打开频率最高的写页面，值得为它定一次"轻记录"的语法；而且方案 A 的所有组件（display 衬线标题、chips、sheet、行内元数据）在现有 App 里都有成熟实现，重构是**重新排列已有语言**，不是发明新东西。B 方案修完仍是一张"轻内容的重表单"，第一性问题只解决一半。
