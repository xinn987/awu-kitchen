## 0. 先说一个重要发现

**上一轮被我推翻重做、又被 revert 掉的"开放纸面化"改版，本身就偏离了设计稿。**
设计稿的家庭页恰恰是**白卡片布局**（`bg-card rounded-xl border`的成员卡、邀请虚线卡、说明卡），编辑页输入框是**白底描边**（`bg-card border border-border`）。也就是说：你觉得"不好看"的那版改版，方向错在用"去卡片"对抗设计稿的卡片语言。设计稿才是这套视觉的宪法，此后的迭代都应该先对照它。这也解释了为什么那个方向怎么看怎么别扭。

## 1. 设计稿的"宪法"（从源码提炼的第一性原则）

1. **三色分工，互不越界**
   - **橙 #BF5924 = 行动**，且只以"轻量"形态出现：FAB、激活筛选、文字按钮（保存/编辑/添加/邀请）、focus ring。设计稿里**没有大体积的橙色块按钮**（FAB 是唯一的圆形实体，48px）。
   - **琥珀黄（amber 系）= 状态警示**：待补充徽章（amber-100/700）、编辑冲突警告卡、详情页"还没有成功关键"警示卡，全部是琥珀系。
   - **绿（emerald）= 成功/转正**：草稿补了成功关键后，编辑页出现 emerald 色提示卡"补充了成功关键，保存后将正式存入食谱库"。
   - 纸色/白色 = 容器。灰 = 系统文字。
2. **衬线/黑体双轨制 = 两种声音**
   - **衬线（Noto Serif SC）是"食谱内容的声音"**：页面大标题、卡片标题、成功关键（展示与输入都是衬线）、收录面板的名称/关键输入框。卡片上的成功关键预览是**斜体**衬线。
   - **黑体（Noto Sans SC）是"系统的声音"**：标签、meta、食材、步骤正文、所有 label 和说明文字。
3. **section 标题是"系统的声音"**：13px 黑体、`foreground/50` 灰、`letter-spacing: 0.08em`。不是衬线，不带图标。
4. **两套输入框语言，按所处底面区分**
   - 纸色页面上：**白底 + 描边**（bg-card border-border），focus 时橙 ring——输入框是"纸上的白卡"。
   - 白色 sheet 上：**灰米底无边框**（input-background #EDE6DA）——靠底色区分。
5. **编辑页是模态任务**：导航栏三段式「取消 / 编辑食谱 / 保存」，**保存是右侧橙色文字按钮**；冲突与转正提示以彩卡插在表单顶部。
6. **成功关键是英雄区块**：详情页唯一使用 wash + 橙边条（3px/40%）强调的内容。
7. **家庭可见性**：食谱库标题右侧是**成员头像堆叠**——"这本食谱书是大家的"被放在第一屏。
8. **邀请是轻状态**：虚线边框按钮"邀请家庭成员"（等待态），不是行动号召。

## 2. 当前实现 vs 设计稿：逐项对照

### 2.1 一致的部分（底子保住了）

- 核心色板：背景 #F4EFE6、主色 #BF5924、secondary #EAE3D8、input 底 #EDE6DA 与设计稿 token 完全一致（app.scss 就是按它建的）
- 食谱卡结构：标题/类型徽章右置、关键预览 + 橙边条、标签 + 头像时间、待补卡虚线底——结构同源
- 详情页版式：标题区/成功关键/食材/步骤的分节 + 细分隔线，成功关键 wash + 橙边条（3px 等值），食材两栏行 + 细分隔线，步骤序号圆——基本忠实
- 历史时间线：圆点 54rpx≈设计 56rpx、当前版本橙底、快照块 secondary 底 + 描边——一致
- 收录面板：白 sheet、把手、灰米输入底、下一步/正式存入主按钮 + 待补文字按钮——一致
- 底部导航结构（双 tab + 中央 FAB）、原生风格 toast（深底浅字）

| 7 | **邀请形态** | 虚线边框按钮（等待态） | 通栏橙色大按钮（行动态） | 设计把"邀请"视为低频等待动作；现状给了最高行动量级 |

### 2.4 设计稿没有、mp 新增的部分（漂移的另一半来源）

评论页、食谱选项页、废纸篓、AI 导入页、编辑页的图片/折叠/主食材、历史 diff——设计稿完全没画。这些页面各自从 token 里"自由发挥"，是风格跳脱的另一半原因。**需要的不是补设计稿，而是一份从设计稿语法推导的"延伸规范"**（写在 app.scss 注释或 docs 里），例如：

- 新页面同样遵守：输入框=白卡描边（纸面）/ 灰米底（白卡上）；警示=琥珀；行动=橙文字按钮优先
- 主食材四角星这类新语义标记：允许，但限定品牌橙单色

## 3. 第一性分析：为什么会漂移

1. **功能迭代没有回锚机制**：评论/图片/导入等功能设计稿没画，实现时只能"凭感觉"从 token 取值——每次取值都是一次微漂移（ink-2、danger、FAB 阴影都在这类迭代中悄悄变了）。
2. **交互优化覆盖了视觉语法**：为了"保存更顺手"把保存做成底栏大按钮；为了"邀请更显眼"做成大橙按钮——每次单点交互优化在局部是对的，但都朝"放大行动"方向叠加，整体上推翻了设计"行动轻、内容重"的层次哲学。
3. **色彩语义被单向合并**：琥珀/绿的语义没有 token 化，所有警示/状态都用橙表达，橙色被迫通胀（这解释了此前 review 里观察到的"橙色通胀"——根源不是用得多，是别的颜色没接班）。
4. **没有把设计稿"跑起来"看过**：此前所有 review 都基于小程序自身截图做内部对比，没有外部基准。这次把设计稿跑起来逐屏对照后，很多"品味问题"其实有明确答案。

## 5. 需要产品拍板的问题

1. **保存位置**：设计稿的 navbar 文字按钮在超长表单（含图片、折叠区）下是否够用？折中方案（滚动后浮现底部保存）是否接受？
2. **首页标题**：回归设计稿的「家庭食谱 + 成员头像堆叠」，还是保留品牌名「阿呜厨房」（可两者兼得：品牌 eyebrow + 家庭标题 + 头像堆叠）？
3. **邀请按钮量级**：邀请在你们的增长路径里是否是核心动作？是→保留大按钮（偏离设计有理）；否→回归虚线轻按钮。
4. **待补充徽章的琥珀色**：会与"成功关键"的橙色边条形成新的色彩关系，确认接受琥珀作为品牌色板的一部分。

## 6. 一句话总结

设计稿的语法是「**内容用衬线说话、状态用琥珀提醒、行动用橙色轻声说**」；现状在功能迭代中让行动变大、让橙色兼任警示、让输入态吞并展示态——回归不是重做，而是把这三条语法重新立起来，并为设计稿之外的四个新页面补一份延伸规范。

## 补充结论（2026-08-30，吸收外部 review 后修订）

吸收了一份外部 review 的有效输入，已逐项验证事实。修订如下：

### 采纳（此前未考虑到的）

1. **字体渲染漂移（已验证，升级为 P0）**：小程序入口只加载了 noto-serif-sc-500.woff2 一个字重文件并注册为 weight 400，而全项目有 50 处 font-weight: 500/600 声明——衬线标题在真机上会以合成粗体渲染，比设计稿的 Noto Serif SC 600 更黑更硬。这是此前所有截图 review 都无法察觉、只有对照字体资源才能发现的「实际渲染漂移」。修复：补齐 400/500/600 三个字重的子集并正确注册 weight；同时明确安卓黑体回退是接受的政策还是需要引入 Noto Sans SC。
2. **间距无制度（已验证，采纳）**：全项目 margin/padding/gap 用了 24 种以上取值（含 5/6/7/14/18/22/26/30/34/36/44/56rpx 等奇数档），颜色/字号/圆角有 token、间距没有。主流程因复刻设计稿而稳定，扩展页各自为政——这是「单页不难看、切页略跳」的技术根源。修复：建立 6 档间距 token（建议 8/12/16/24/32/48rpx 基础档 + 40/64rpx），新代码强制、老代码渐进。
3. **吸底保存定位修订**：外部 review 认为吸底保存比设计稿的 navbar 文字按钮更适合小程序长表单，是「被认可的演化」而非偏离。采纳该立场，撤回本文 §4 中「保存回归 navbar」的建议；相应地，行动体积问题改由琥珀/绿接班（§2.2-1）与输入框语言回归来消化，不再与保存栏对抗。
4. **区块标题收敛方案细化**：收敛为两种无衬线模式——内容页用小号低对比灰字（设计稿语法），管理页用正文级字重；衬线只保留给食谱名、家庭名与经验内容。修正本文此前的「衬线小标题」建议（与设计稿不符，且已被 revert 证实不受欢迎）。
5. **品牌眉题的「孤立」判断**：AWU KITCHEN 只出现在食谱库一页、无其他品牌语法承接，处于「品牌」与「家庭资料库」之间的暧昧态——比简单删除更准确的表达。去留仍是 §5-2 的产品决策，但无论选哪边都要成体系（选品牌则 onboarding/空态承接；选家庭则恢复头像堆叠）。

### 维持原判（外部 review 未覆盖、证据不变的）

1. **琥珀/绿三色语义缺失仍是 P0**——外部 review 完全没有涉及这一点。设计稿源码明确：待补充徽章 amber-100/700、编辑冲突卡 amber 边框、转正提示 emerald 卡（App.tsx 的 DraftBadge / showConflict / wasDraft&&wouldBeFormal 三处）。这是设计语法里与橙色分工的另一半，不恢复它，橙色通胀无解。
2. **语义色 token 漂移**：外部 review 的对照表称「配色高度一致」，但只核对了主色板。--ink-2 #6f6257 vs 设计 #7C6F63、--danger #b3402a vs 设计 #C0392B 仍是实际漂移。
3. **编辑页输入容器**：设计稿编辑输入框是白底描边（bg-card + border），现状是纸深底无边框——外部 review 未提及。在采纳「保留吸底保存」后，输入语言回归成为编辑页对齐的主要抓手。
4. **底部导航白底、FAB 阴影/尺寸、卡片预览斜体**等细节项维持。

### 修订后的 P0/P1 合并视图

- P0：琥珀/绿语义 token 化并落四个组件；字体子集补齐与 weight 注册；编辑输入框回归白卡描边
- P1：间距 token 立法；区块标题两模式收敛；详情页底栏层级（评论 + 完善 + ⋯ 收纳复制/归档，沿用已验证过的方案）；扩展页（设置/选项/导入）按容器语义重排
- P2：色值回归（ink-2/danger）、导航白底、FAB 规格、斜体、品牌体系化、空态
